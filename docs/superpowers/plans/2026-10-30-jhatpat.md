# JhatPat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Owner preference:** execute inline with superpowers:executing-plans (no subagents).

**Goal:** A single Go binary that runs a LAN web server so phones (browser only) and the laptop exchange files, folders, text and links, with PIN + approval, per-device/group privacy, resume, and a Network Doctor.

**Architecture:** Go stdlib `net/http` server, all state in small focused packages under `internal/`, realtime via Server-Sent Events, UI as vanilla HTML/CSS/JS embedded with `go:embed`. The laptop is the hub; every item has a server-enforced recipient set.

**Tech Stack:** Go (latest stable), stdlib only plus `github.com/skip2/go-qrcode` (pure Go QR). No JS framework, no CDN, no build step for web assets.

**Spec:** `docs/superpowers/specs/2026-10-30-jhatpat-design.md`

## Global Constraints

- Single self-contained binary; end users install nothing else.
- No network access to the internet at runtime; all assets embedded.
- Never load a whole file into memory (stream to/from disk).
- Default port `8787`; if busy, try the next port up to `8797`.
- PIN: 4 digits, regenerated each run and on "New PIN". Join secret: 32 random bytes, base64url.
- Lockout: 5 wrong PINs per IP per 5 minutes; global PIN lock after 20 failures until New PIN.
- Every device needs host Allow on every run (approvals never persist).
- Device token: random 32 bytes, cookie `jp_dev`, HttpOnly, SameSite=Strict, Path=/.
- Items not addressed to the requester → HTTP 404.
- Upload chunk size `8 MiB`; text cap `1 MiB` (larger → error telling client to send as file).
- Save folder default `<UserHome>/Downloads/JhatPat`; config dir `os.UserConfigDir()/JhatPat`.
- Folder downloads: on-the-fly zip, `zip.Store` method.
- Plain HTTP on LAN (v1).
- Module path `jhatpat` until the owner's GitHub username is known (Task 14 renames).
- UI style "Sunny Pop", light + dark (follow `prefers-color-scheme`, manual toggle stored in `localStorage`), English base + Roman Urdu.
- License MIT.

## Review Focus

1. Phone sends a file named `../../evil.txt`, `CON.txt`, `a:b?.jpg` or an emoji name → saved safely inside the save folder with a valid Windows name, emoji kept. *(test in Task 7)*
2. Two uploads of `photo.jpg` at the same moment → both saved (`photo.jpg`, `photo (1).jpg`), neither overwritten. *(test in Task 7)*
3. Disk full / write error mid-upload → client gets a clear error, no half file renamed to the final name. *(test in Task 7)*
4. Laptop changes WiFi or IP while running → Network Doctor re-check returns the new IP and the QR/URL update. *(test in Task 10)*
5. Phone browser is backgrounded mid-upload (iOS) and returns → upload continues from the server's received offset. *(test in Task 7, resume)*
